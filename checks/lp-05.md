# LP-5 — Scanning what the owner sent (email + iMessage)

## What changed

- `scan-mail.ts`: one fixed argv per account, `SENT_ARGV(account)` =
  `plow-gog gmail search "in:sent newer_than:2d" --max 25 --json --account <a>`
  (the S1 command plus `--account`). New messages are cut locally against a
  per-account cursor `{at, ids}`. Rows not from the account, auto-replies,
  list mail and notes to self are dropped. A row without a body is read from
  subject + snippet and reported as `degraded: mail-no-body` (S2 fallback).
- `scan-imessage.ts`: fixed argv `plow-messages search --limit 200 --order desc`
  (read_paths `~/Library/Messages`), cut locally by rowid. Only `is_from_me`
  rows in direct chats; group chats and received messages are skipped. If
  all 200 rows are past the cursor, `degraded: imessage-gap`.
- `prefilter.ts`: deterministic, Portuguese and English, high recall.
  `ownText` strips quoted history, `>` lines and signatures, so the other
  side's words in a reply never become the owner's commitment. Drop reasons
  are counted: `auto_reply`, `mailing_list`, `self_recipient`,
  `attachment_only`, `empty`, `too_short`, `no_commitment_phrase`.
- `cursor.ts`: per-source cursor, two phases (`scan` writes a pending file,
  `commit` moves the cursor), Meetly's fail/ok/warn-after-30-minutes, and
  `health` (last successful read per source, for the digest).
- `scan-common.ts`: the candidate shape, the cap and the walk.
- Setup now probes each source with the scan's exact argv while the owner is
  present, and asks them to choose "Always allow" (FT MP-2).

## Decisions and deviations

- **Cap order.** The plan says "40 per poll, newest first; the rest wait and
  the cursor does not pass them". A high-water cursor cannot skip older rows
  and keep them for later, so the scan takes the **oldest** 40 new
  candidates and stops the cursor after the 40th; the rest come in the next
  poll. Nothing is lost, and with a poll every 15 minutes the cap only binds
  on unusual bursts.
- **First run.** The first scan of a source only marks where "new" starts
  (`initialized`); it never reads history. Looking back two weeks is the
  backfill, with the owner present (LP-13).
- **Deadline words alone** do not keep a message ("até amanhã!" is a
  goodbye); a promise, request or delegation phrase is required. Delegation
  = an imperative plus a deadline marker.
- The poll skill is not wired to the scanners yet: committing a scan's cursor
  before the candidates can be recorded would lose them. The poll uses them
  from LP-7, when detection exists.

Everything about the tools' real output shape is still an assumption until
the on-Mac spikes (S1–S3, `checks/lp-00.md`); the parsers accept the common
shapes (a list, or a list under `messages`/`threads`/`results`, ISO/RFC 2822/
epoch dates, `to` as a string or a list).

## Checks

```
$ npm run typecheck
(exit 0)

$ node --test --test-reporter=tap tests/prefilter.test.ts tests/scan.test.ts tests/skills.test.ts
# pass 14
# fail 0
```

Required by the plan and covered in `tests/scan.test.ts`: identical argv
between runs; the cursor moves only on `commit`; a repeated scan without
commit hands over the same items and the pending file holds no duplicates;
a `blocked` Latch → `degraded` + `cursor fail`, with the owner warned once
after 30 minutes; a source that is off makes zero calls to the Mac.
