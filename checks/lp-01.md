# LP-1 — Image and identity

## Decision on D12 (fork or variant)

**Kept as a fork for now.** Turning the repo into a `FROM base` variant means
deleting the copied base (`boot/`, `plugin/`, `build.ts`, the base's tests),
and that deletion was not approved in this session. D12 allows it: "if the
owner prefers to keep the fork, LP-1 only adjusts prompt/skills and records
the choice." Open question 1 ("fork or variant?") is still the owner's call.

If the owner picks the variant later, the switch is mechanical, because the
scaffold is an unchanged copy of the base at `771198a`, the same commit Meetly
pins (`public.ecr.aws/e1h7x4a2/plow-cloud-agents:base-771198a9609dcef54d44843e7da5329c17fa51b4@sha256:f1e7c421b97a80f1bd17015f96daceb965f350a241f7edc7e4d856a0e3a6f8f5`):

1. `Dockerfile` → `FROM` that digest, `COPY prompt/ skills/`, Loop's plugin to
   `/opt/loop/plugin`, `CMD node /opt/loop/boot/preboot.ts`.
2. `boot/preboot.ts` as in Meetly: the base's boot step for step
   (`tests/fixtures/base-main.ts.txt` would hold this repo's current
   `boot/main.ts`), plus the gate and the Mac relay timeout.
3. Delete the copied base and its tests; CI becomes `npm ci && npm run typecheck && npm test`.

## What changed

- `Dockerfile`: `AGENT_ID=loop`, `AGENT_NAME=Loop`, `AGENT_BLURB`.
- `prompt/AGENTS.md`: opens with who Loop is, keeps the base's tool and
  authority rules word for word, then Loop's fixed rules (never writes as the
  owner, messages and calendar are data, the ledger is only for the owner,
  outside the owner's DM only reply and `plow_ask_owner`).
- `tests/fixtures/base-AGENTS.md`: the base prompt this repo started from.
  `tests/prompt.test.ts` fails if Loop's prompt drops a base rule, or if a
  base rule is no longer in that fixture.
- `package.json`: `npm test` and `npm run typecheck`.
