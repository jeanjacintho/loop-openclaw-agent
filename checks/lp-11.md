# LP-11 — Drafts (Prepare)

## What changed

- `skills/loop/scripts/draft.ts`:
  - `plan --id X`: where the follow-up goes. The recipient is always the
    other side of the commitment, from the ledger; there is no `--to`
    anywhere (Review Focus 1). A commitment that started in Gmail is drafted
    in that thread, replying to the owner's message (`account`, `threadId`,
    `replyToMessageId` from the evidence item); one that started in
    iMessage gets text for the owner to paste; no email/phone → error, ask.
  - `create --id X --body TEXT`: refuses an empty body, more than 1,200
    characters, or any email/phone that is not the recipient's (no third
    parties); money like "1.500.000" is not mistaken for a phone. Gmail →
    `plow-gog gmail drafts create …` (argv as assumed by S4, `draftArgv`); if
    that fails, the owner still gets the text. Records `drafted`.
  - Loop never sends: no texting from the owner's Messages, drafts only.
- `resolve.ts nudges`: an owner message to someone who owes them (same
  thread, naming the object, or after a draft) → evidence + `nudged`,
  once per message. The digest then waits 2 days before listing that
  overdue item again ("reinicia a janela de espera").
- `skills/loop-owner/SKILL.md` (new): digest numbers via `digest.ts item`,
  and the follow-up flow (plan → write as the owner, in the conversation's
  language, only about this commitment → create → tell the owner where it is).
- The poll records nudges before committing; the prompt routes digest replies,
  "chase"/"cobra" and "what do I owe?" to `loop-owner`.

## Assumption to check (S4)

`draftArgv` is `plow-gog gmail drafts create --account A --to T
--reply-to-message-id M --body B --json`. If `plow-gog` names these flags
differently, only `draftArgv` changes; if drafts do not exist at all, every
draft falls back to text in the DM (already handled as `drafted: false`).
