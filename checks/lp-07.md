# LP-7 — Detection: extract, classify, record

## What changed

- `skills/loop-poll/SKILL.md`: the poll now scans each source, has the
  model extract each candidate (the **Extract** section: the JSON contract,
  what is and is not a commitment, the features), records it with
  `detect.ts record`, and only then commits the scan's cursor. A 30-minute
  run of read failures sends the owner one DM, with Latch's `ownerAction`
  word for word.
- `skills/loop/scripts/detect.ts`: what the script decides, not the model:
  - only a candidate from the last scan (the pending files) can be recorded;
  - the quote must be a substring of the owner's own text (whitespace
    normalized), or the call is refused;
  - the band comes from the features (`confidence.ts`, with the calibration
    offset from the `calibration` table, 0 until LP-12);
  - the other side comes from the message's recipients: the model's handle
    only picks among `to`; one recipient is that recipient whatever the model
    wrote; CC-only or several recipients with none named → capped at
    `candidate` (F21);
  - the deadline is `deadline.ts` on `deadline_text`, from `sentAt`;
  - `updates` (renegotiation → `deadline_changed`, cancellation →
    `dropped`) must point at a live commitment with someone the message went
    to (Review Focus 1 and 3).
- `migrations/002_detections.sql`: every recorded extraction (item, band,
  features, the commitment it became), for precision by band later, and the
  `calibration` row.
- `tests/fixtures/eval/detection.json` + `checks/eval-detection.ts`: the
  eval, offline (labelled features through `confidence.ts`) or `--live`
  (the real model, asked exactly the poll's Extract section).
  `tests/eval.test.ts` keeps the offline result above the bar.

## The eval set is synthetic — the gate is not met yet

The plan asks for ≥ 80 **real** messages from the owner, anonymized, with
permission. This container has no access to them, so the set here is 84
hand-written messages (Portuguese and English: promises, requests,
delegations, pleasantries, hypotheticals, past tense, renegotiations,
cancellations, other). It checks that the weights and the prefilter behave
as designed; it does **not** measure the model. Before the review gate:

1. replace or extend the set with the owner's real messages (same format);
2. run `node checks/eval-detection.ts --live` with `PLOW_API_BASE` and
   `PLOW_AGENT_TOKEN` set, and paste the table here.

The weights alone reach 0.92 on `open`; the four false opens are all past
tense ("I sent you the deck yesterday"): only the model's `is_commitment`
can tell those apart, which is why the Extract section lists them as "not a
commitment". Pleasantries and hypotheticals never reach `open`.
